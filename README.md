# 铁路信号联锁测试用例编排与回归记录平台

源提示词编号：14。包含道岔、信号机、轨道区段与进路关系，Canvas 站场缩放与定位，受设备变化影响的回归范围推导，用例步骤/预期/依赖编排，实时执行同步、断线重试、失败证据、基线锁定和测试报告导出。

## 拓扑修订（StationDevice / RouteRelation / TestCase 共用）

站场图、进路几何、受影响用例与发布报告统一引用同一个拓扑修订号（`revision`），不再各画各的坐标：

- 进路只声明节点链 `nodes`（设备节点 + 股道折点），几何点由设备锚点（道岔区分定位/反位锚点）统一重算。
- 设备坐标或道岔位置提交后，只重算关联进路与锚点（`recomputeAffectedRoutes`），用例沿“设备 → 进路 → 用例”推导受影响范围并刷新修订号。
- 校验出断开、环路、重复锚点、缺失设备或反位锚点缺失时，修订停在「待处理」并指出节点（红色高亮），现行拓扑保持旧修订不变。
- 两个制图员同时提交同一站场：先到版本生效；基线修订号过期的后到提交标记「已拒绝」，其现场坐标与差异保留在 `retainedDraft`，可一键装回编辑区重提或放弃。
- 离线回传按修订号逐设备合并（`anchorRevision` 新于现行才采用），合并后仍走同一套拓扑校验。
- 写入失败时先取完整站场备份（设备/进路/用例/执行记录/修订号），失败即整体回滚恢复，不留半成品，恢复记录在站场页展示。
- 旧版数据没有道岔位置：恢复时升级为默认定位、按岔心偏移补全反位锚点并标记 `needsReview`（待复核，不阻断）。
- 基线锁定时冻结拓扑快照（设备锚点 + 进路节点链 + 修订号 + 时间），发布报告 JSON 携带该快照，事后可追溯发布时现场坐标。

站场页提供场景模拟按钮：并发提交、断开坐标、重复锚点、离线回传、旧版备份恢复、强制写入失败。

## 技术栈

Vue 3、Naive UI、Pinia、Vue Router、TanStack Query、Axios、WebSocket 模拟、Canvas、Vite、TypeScript。
